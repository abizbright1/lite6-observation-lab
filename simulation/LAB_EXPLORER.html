See how observation errors become positioning errors

An offline learning simulator and a bridge to a measured robot experiment.

The stationary target is on a plane. A moving wrist camera observes it, then a decision checks a fixed proposed tool position. Change the faults, predict the outcome, and compare the observation with evaluator-only truth.

This is a simplified 2D affine model, not a Lite 6 digital twin, robot controller, or demonstration of a new research algorithm. All displayed distances and bounds are teaching assumptions. No hardware connection is present.

Derive what the simulator calculates
For each axis, exposure pose rc = rd − v·a, and the observation z = s·(p − rc) + b + n. The naive estimator uses p̂ = rd + z. The interval estimator considers p = rd − v·a + (z − b − n)/s for every endpoint of the declared age, bias, noise, and positive scale intervals. This expression is monotone in each variable when the others are fixed, so its extrema over this box occur at corners. It subtracts the fixed command to obtain the error interval. It approves only if both intervals lie within ±3 mm and the metadata requirements pass.
Increasing age does not create geometric error when velocity is zero and the scene is unchanged. A finite bound can fail when the actual age or bias exceeds it, or when the observed object is different. The evaluator can expose such failures; the online policy generally cannot see the hidden cause.

3. Inject errors without confusing them with real evidence
Start with saved logs or synthetic data. Never obtain a failure label by executing a known invalid descent. Every injected copy retains its original session ID, so copies cannot leak across development and test splits.

Keep the three kinds of data separate
  1. Online evidence: what the camera/robot/logger actually supplies to a method. No hidden true fault severity or reference outcome.
  2. Evaluator truth: known synthetic state or independently measured physical reference, used only after decisions are fixed.
  3. Analysis: join by episode and attempt ID, then report acceptance, false approval, abstention, latency and uncertainty coverage. Keep all stopped and failed attempts.
