Offline planar observation simulation

This lab is a runnable measurement-and-decision simulator, not a robot digital twin. It teaches how a stationary planar target can be mislocalized when camera coordinates are combined with the wrong robot pose, clock mapping or geometric calibration. It runs with Python 3.9+ and its standard library. There are no robot SDKs, cameras, network requests, external packages or hardware actions.

Start here

From Terminal:

cd path/to/your/repository
python3 simulation/planar_lab.py --output simulation/generated
python3 -m unittest discover -s simulation -v

The supplied run contains 768 complete independent simulated episodes: 12 scenarios, each with 12 training, 12 calibration and 40 test episodes. Each method receives identical raw packets and clock/metadata information. Camera frames inside an episode stay in one split. Baselines and deterministic supports are frozen analytical teaching assumptions; training/calibration data are reserved practice partitions and are not used to fit or certify the bounds. Do not describe them as a calibrated learned model.

To explore your own configuration, copy default_config.json, change one field, and run:

python3 simulation/planar_lab.py --config simulation/default_config.json --seed 17 --output simulation/practice_seed17

Use a new output folder for a new experiment; reusing a folder replaces that folder's generated files. Do not change test settings after viewing failures and then call the same test set held out. Keep an untouched seed/session for final evaluation.

Exact model and units

Every spatial coordinate is millimetres, velocity is mm/s, time is seconds and scale is a dimensionless fraction. ppm means parts per million. The target p=(px,py) is stationary. Nominal camera translation is r(t)=v*(t-origin) in each axis. Its raw local metric feature is:

raw = (p-r(capture))*(1+scale) + bias + noise
camera_stamp = capture*(1+clock_drift) + nominal_offset + offset_error
host_receive = capture + transport_delay

The monitor gets the raw feature, receipt time, camera stamp, nominal trajectory and reported marker ID. It never receives true capture time, true scale, true bias, actual target, injected-fault flag or the reference label. It forms a capture-time interval using the frozen clock mapping support and causal receipt time. Its exact per-frame independent-box target enclosure is:

p = (raw-bias-noise)/(1+scale) + v*(decision-origin-age)

Enumerating box corners is exact for this restricted scalar fractional/affine expression with positive denominator. The x/y Cartesian product is a conservative single-frame independent-box baseline. It does not preserve cross-frame shared-parameter correlations. It is not the proposed dissertation algorithm or a full joint feasible-set solver. There is no pixel image rendering, yaw, perspective, nonlinear camera distortion, image detector, robot joint dynamics or contact model.

The fixed nominal command is (100,100) mm and the success criterion is a square with 3 mm tolerance per axis, not a radial 3 mm circle. A bounded constant execution offset of at most 0.15 mm per axis covers the entire 80 ms synthetic action. Actual robot residual motion, vertical descent, collision, suction, contact and attachment success are not simulated. The fixed command comparison is a lesson; an optimized-command baseline is required for research claims.

Compared methods and equal budgets

  1. current_measurement: combine raw feature with the current nominal camera pose; threshold the resulting point.
  2. age_compensated_point: compensate that point using the midpoint age estimate; threshold the result.
  3. bounded_interval: contain the full declared target interval plus execution-error bound inside the fixed tolerance square.

All methods have common receipt/ID/sequence guards, decision opportunities at 140, 200 and 260 ms, the same packets and the same final deadline. First approval terminates that method. A rejection can wait for another already scheduled observation; there is no extra private reacquisition budget. Mean decision latency is simulated waiting time, not measured CPU runtime, hardware cycle time or action completion time. Add 80 ms for the simple synthetic action duration after approval. No method physically stops the camera or requests a new sensor action. The stationary scenario is the zero-motion null test; it is not a separate stop-and-fresh policy.

If no method approves, false approvals per approval is null, not zero. Always refusing to act is not evidence of useful performance.

Fault matrix and data generation

scenario_matrix.json lists each case. Default bounded supports: bias ±0.6 mm; scale ±0.002; feature noise ±0.1 mm; camera offset uncertainty ±3 ms; drift ±25 ppm; independent target-reference noise ±0.05 mm. These are illustrative values, not measured properties of your OAK/Lite 6 station.

Changing bound settings changes normal generator support; stress magnitudes are at least the listed amounts and increase if needed to remain out of bounds. Marker association errors are metadata/data faults, not a justification for moving a real robot toward the wrong object. Physical faults should first be injected into copied offline logs. Keep ordinary unmodified real trials as a separate dataset; extreme injected cases do not establish everyday practical relevance.

Files and the truth barrier

  • observations.csv: public raw packet fields only; episode IDs are opaque hashes. Scenario and split labels are kept in evaluator files, not online packets.
  • decisions.csv: monitor outputs, chosen frame, attempt, approval/reason, interval and simulated latency; no evaluator labels.
  • truth.csv: simulator-only target/capture times, calibration parameters, noise, tracking offset, reference reading and hidden fault flags. Keep away from model inputs.
  • evaluation.csv: evaluator joins decisions to truth after execution; contains actual validity, false approval, independent-reference label and interval containment.
  • summary.json: matched scenario/split/method metrics and assumptions.
  • config.json: frozen run settings.
  • manifest.json: SHA-256 hashes of generated files and generator source for reproducibility.

The noisy independent reference is generated from the true target, not from the vision estimate. Reference labels are valid/invalid/ambiguous after propagating reference and execution uncertainty. The simulator separately reports exact truth labels for learning; physical experiments will not have those exact labels. Do not resolve ambiguous physical measurements using the method under evaluation.

What the default results actually show

For the default seed, nominal-motion test approvals are 10/40, 9/40 and 3/40 for current, compensated and interval methods, with 5, 1 and 0 false approvals respectively. These are deliberately small teaching samples. The interval method approves nothing in several cases; inspect this loss of utility. Its hidden-wrong-association test does false-approve (1/40), as do other violated-support cases. The supplied tests explicitly require this failure to remain visible. Zero observed failures inside the generated support are a model-consistency check, not a physical guarantee or novel research result.

Mapping to your eventual physical experiment

  1. Record your actual model/serial numbers, camera mounting height/orientation, target plane, calibration version, robot tool frame and independent reference setup. Replace every illustrative support with justified physical evidence; sample maxima alone are not deterministic guarantees.
  2. Preserve raw image frames, device exposure timestamp and clock domain, host receipt/dequeue time, robot pose timestamp and clock domain, commanded/actual pose, sequence/session IDs and target association evidence. Do not substitute host dequeue freshness for exposure age.
  3. Start with replay/recording, then independently supervised and approved station procedures. No movement is required by this code. Read the robot repository's owning AGENTS.md before any future integration.
  4. Split whole physical sessions/cycles across development, calibration and held-out testing; freeze method settings before held-out evaluation.
  5. Independently measure lateral tool/target relationship and reference uncertainty. Report uncertain labels as ambiguous. A reference that is too coarse cannot establish a small improvement.
  6. Measure ordinary stationary fresh-capture performance before injecting timing errors. If ordinary calibration and settling already solve the problem within tolerance, that is a legitimate no-go for the proposed research claim.
  7. Add a full shared-parameter joint solver, strong uncertainty-aware point baseline, optimized commands and a genuine stationary reacquisition policy before claiming an algorithmic advantage. Match observation/action budgets and measure CPU runtime separately from physical latency.

Validation included

test_planar_lab.py checks exact interval signs/corners and invalid inputs; all-packet containment in hundreds of within-support episodes; stationary age invariance; independence from truth modifications; session partition/reproducibility; matched observation deadlines; duplicate/reordered rejection; hash integrity; label separation; undefined rates; and visible failures outside the assumptions. These tests establish only the implemented toy's properties.
