Blank real-data templates

These files contain headers only, not collected observations. Copy into a new session directory and fill metadata from actual evidence. No equipment inventory, timestamp accuracy or physical result has been verified by these templates.

  • Policy-visible input: camera_observations.csv and robot_telemetry.csv, limited to fields actually available in deployment.
  • Policy output: decisions.csv.
  • Evaluator-only: independent_reference.csv, outcomes.csv and replay_injections.csv. Do not feed these labels into a method unless explicitly defining a separate reference-assisted baseline.
  • Keep original data immutable. Derived replay input may contain an altered reported timestamp, but preserve the untouched source file and evaluator ledger.
  • Every time requires a clock ID and source. Original host receipt/dequeue, logger write time and injected replay delivery are different events. Blank unavailable times and explain missing_reason; zero is a real value.
  • source_frame_id/sequence and sensor_session_id identify original observations; episode_id/attempt_id distinguish decisions or reacquisitions. Duplicated delivery keeps the original source ID.
  • *_json cells contain valid JSON, e.g. an array of source IDs; use a proper CSV writer. Boolean values should use true/false consistently. No example trial rows are supplied.
  • Obvious duplicate/out-of-order flags may be computed from observed IDs, but injection truth flags remain in the evaluator-only ledger. A simulator can know a hidden fault that the real policy cannot.
  • Preserve calibration/registration/configuration hashes and version the schema if extending columns. Raw device identity may be kept locally; sanitize exports as appropriate.
  • Read ../PHYSICAL_SETUP_AND_DATA_PROTOCOL.md for uncertainty, event definitions, held-out sessions, stage gates and fair comparisons.
