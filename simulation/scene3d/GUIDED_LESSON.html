Before you begin

This is a visual and kinematic simulation. It does not control the physical arm, validate a real camera, simulate contact, or prove a safe motion. Rendered camera features come from known scene geometry. All values shown below are virtual or explicitly assumed until independently measured in the lab.

In the viewer, the large panel is the environment. The upper camera panel is the current wrist-camera view. The lower camera panel is the received image, which may be old. The separate reference view is another virtual camera; it is not physical ground truth. The orange point is calculated from the scene geometry, not found by an AI detector.

Chapter 1 — Meet the experiment

The Lite6 moves around a stationary target. A camera is rigidly mounted at the wrist. The camera image is useful only when we know how its pixels relate to the robot's coordinate frame. The virtual reference camera helps us understand an independent measurement arrangement. A real reference system needs its own calibration and uncertainty check.

Look for: robot base, tool tip, wrist camera, flat target plane, target, calibration artifact and reference camera. Orbit the model and compare the side and top views.

Chapter 2 — Three views, one event

The live wrist view shows what the virtual camera sees at the current pose. The received view shows the image supplied to the estimator. The reference view shows the virtual scene from another direction. If the robot is stopped and the scene is unchanged, an old frame can still describe the same target position.

A frame has several times. Exposure is when the camera took the image. Receipt is when the computer received it. Decision is when the algorithm used it. These are not interchangeable.

Chapter 3 — Pixels become positions through geometry

A pixel coordinate (u, v) is measured in pixels, not millimetres. To estimate a position, use camera intrinsics, the camera pose in the robot base frame, and the known target plane. Cast a ray through the image feature and intersect it with the plane. The resulting point is expressed in the chosen robot frame.

Virtual example: the viewer places the target at (X, Y) = (290, 20) mm on the plane Z = 30.5 mm. Its rendered feature is approximately (u, v) = (253.8, 203.8) px for the example camera pose and focal length. Inverting the projection returns about (290, 20) mm. This checks the viewer's geometry. It does not test a physical camera or vision model.

Chapter 4 — Image age while nothing moves

Select the stationary delayed-camera chapter. The viewer advances to 1.00 s. Its capture grid is 0.10 s; with a 0.65 s delivery delay, the image exposed at 0.30 s arrives at 0.95 s.

  • Image age at decision: 1.00 − 0.30 = 0.70 s = 700 ms.
  • Time since receipt: 1.00 − 0.95 = 0.05 s = 50 ms.
  • Camera motion: 0 mm/s × 0.70 s = 0 mm.

The image is old, but because the camera and target did not move, age alone did not move the estimated target. Delay is not automatically a position error.

Chapter 5 — Image age while the arm moves

There are two different calculations here. Keep them separate.

Hand calculation for the 1.8 mm example: if an arm is already moving at a constant 60 mm/s and the image is 30 ms old, first convert milliseconds to seconds: 30 ms ÷ 1000 = 0.030 s. Then multiply speed by elapsed time: 60 mm/s × 0.030 s = 1.80 mm. This is a simple constant-speed illustration.

What the 3D viewer actually does: its button steps the simulation by 100 ms, not 30 ms. Its sweep is sinusoidal, not constant speed. At speed-slider value 60, starting phase zero:

  1. Phase change: (60 ÷ 35) × 0.100 = 0.17143 rad.
  2. X displacement: 35 × sin(0.17143) ≈ 5.97 mm.
  3. Y displacement: 18 × sin(0.65 × 0.17143) ≈ 1.99 mm.

The chapter displays the actual exposure time, estimate and tool error recorded by the viewer. It can demonstrate how a stale observation interpreted with a current pose produces a misleading decision. This is a simulated event only.

Chapter 6 — A fresh image can still be wrong

A new image cannot fix a wrong camera-to-tool mapping. For the virtual bias example, the target X coordinate is 300 mm, while the estimate has an assumed +8 mm error and reports 308 mm. If the virtual tool aligns with that estimate, the estimate-to-tool residual can be near zero while the real target remains 8 mm away.

Press Run the virtual alignment example to animate the illustrative sequence. The display separates the point test from evaluator truth. The sequence is only a visualization; it does not perform a pick or send a robot command. The 8 mm bias is chosen for teaching, not measured from your setup.

Chapter 7 — Compare error with a task tolerance

The viewer's point test requires each axis to be within ±3 mm; this makes a square acceptance region. A radial distance is a different quantity. Do not compare radial error to the per-axis threshold as if they were the same test.

A separate protocol example uses assumed per-axis bounds:

  • reference uncertainty: 0.25 mm;
  • geometry uncertainty: 0.40 mm;
  • execution uncertainty: 0.30 mm;
  • timing uncertainty at 20 mm/s over 8 ms: 20 × 0.008 = 0.16 mm.

Total assumed bound: 0.25 + 0.40 + 0.30 + 0.16 = 1.11 mm. These are not measurements. Against a 3 mm limit, an observed error of 1.2 mm gives a worst case of 1.2 + 1.11 = 2.31 mm (pass under these assumptions). An error of 2.1 mm reaches 3.21 mm (uncertain). An error of 4.5 mm has a best case of 4.5 − 1.11 = 3.39 mm (fail under these assumptions).

Chapter 8 — What a real record must contain

For each future physical observation, the study needs a frame ID; exposure, receipt and decision times with clock sources; robot pose and coordinate frame; detected pixel feature and calibration version; estimated target position; independent reference position and uncertainty; decision; and outcome only if a separately permitted physical action occurs. Keep the reference data out of the method's input. Record missing images as missing evidence, not as measured positions.

The current 768-episode batch data and this 3D scene are synthetic. The physical templates are blank. Before collecting research data, validate the camera, timing, coordinate transforms, independent reference and uncertainty bounds with the physical setup protocol.
