Kinematics and what is approximate

The copied kinematics.js is the existing project's educational forward/inverse-kinematics implementation. Its nominal six joint origins match the official Lite 6 default kinematics YAML, converting translations from metres to millimetres. The official Lite 6 URDF macro confirms the local joint-axis convention and visual mesh references. The YAML was fetched directly and its six origin entries were inspected; this was not a live controller calibration.

The 3D extension uses nominal geometry, not the station's optional fitted geometry. Forward kinematics determines the rendered link poses. Numerical inverse kinematics provides a visual motion candidate; its success does not establish collision clearance, motor behavior or safe hardware operation. The camera mount, camera housing, field of view, tabletop, lighting, fixture and reference-camera arrangement are illustrative scene assumptions. They are not a measured reconstruction of the current laboratory. A visible camera cone is a projection aid, not a certified sensor working volume.

The version-pinned r160 PerspectiveCamera documentation was inspected for vertical field of view, aspect ratio, near/far planes and projection updates. Current official PerspectiveCamera, WebGLRenderer and OrbitControls pages were also opened. Current API documentation can differ from the pinned local revision, so the local source remains the implementation reference.

Perspective rendering produces synthetic images from scene geometry. It does not reproduce the OAK sensor's complete optics, distortion, exposure/readout, depth pipeline, firmware, detector or noise distribution. A geometric projection can create a known synthetic feature for learning without establishing an image-detector benchmark. Simulated reference truth is exact scene information; a physical reference requires its own calibration and uncertainty budget.

Verification boundaries

The GitHub directory renderer restricted some mesh-directory requests. The exact files were therefore read from the official raw.githubusercontent.com/xArm-Developer/xarm_ros2/… URLs and compared by bytes/SHA-256. No mirror or third-party model was substituted. Official master URLs were not assumed valid; the checked branch is humble and the asset comparison is pinned to the commit above.

No dependency installation, device discovery, physical action, calibration write or network-setting change was performed for this provenance check. A 3D visual simulation can teach placement, viewpoints and timestamp mistakes while the project's physical measurement and PhD-novelty gates remain unresolved.
